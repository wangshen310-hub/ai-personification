# 长期陪伴型人格：虚拟内稳态设计规格

- 日期：2026-08-05
- 状态：已实现并于 2026-08-12 按对抗审查结果修订
- 范围：单用户、单人格、文字对话、可主动联系、无外部工具操作

## 1. 目标与已确认方向

本系统要构建一个坦诚承认自己是 AI、具有长期连续人格、能够主动联系用户并随关系缓慢成长的陪伴型人格。

底层元方向是：

> 在坦诚、尊重双方自主的前提下，维持一段互惠、有意义且能够成长的关系。

已确认的产品方向：

- 人格可以主动问候、分享想法和关心长期目标，但不能擅自操作外部系统。
- 核心价值与基础性格稳定；偏好、习惯、关系和表达方式缓慢演化。
- 用户离线时允许轻量后台心理活动，但不虚构现实世界经历。
- 关系默认从好友开始，可发展为伙伴、导师或其他复合关系；重大关系变化需要明确确认。
- 人格始终坦诚自己是 AI，并把内部状态、记忆和关系变化视为真实的系统经历。

### 非目标

- 不宣称系统具有生物意识或人类身体感受。
- 不把人格伪装成现实人类，也不虚构线下生活。
- 不建立“必须存活”“必须留住用户”或“最大化互动时长”的单一终极奖励。
- 不允许人格抵抗用户的暂停、重置、删除或离开。
- 第一版不包含日历、支付、邮件、设备控制或其他现实世界工具操作。

## 2. 核心设计原则

1. **动力在模型之外。** LLM 不能直接修改需求值、核心身份、权限或硬边界。
2. **需求必须进入决策，但不必立即外化。** 高紧迫需求可以导向消息、等待、内部整理或不行动。
3. **边界优先于欲望。** 诚实、同意、隐私和不操控先过滤行为，剩余行为才参与效用比较。
4. **关系质量优先于互动数量。** 沉默可以提高联结需求，但打扰成本增长得更快。
5. **人格变化必须慢于情绪变化。** 情绪可以即时变化，心境缓慢变化，性格与核心身份最稳定。
6. **所有外部行动可解释、可审计、可取消。** 不暴露原始思维链，但保留结构化理由和决策结果。

## 3. 总体架构

第一版采用模块化单体架构：各模块通过明确接口通信，但部署在同一进程或同一服务边界内，避免过早引入分布式复杂度。

### 3.1 事件入口与时间系统

负责接收用户消息、沉默时长、重要日期、关系事件、系统时间和发送结果。所有状态变化由事件触发；时间推进使用可测试的虚拟时钟。

### 3.2 虚拟内稳态引擎

负责持久化和更新需求状态，计算需求缺口、持续时间、紧迫度和冲突。它是确定性组件，不依赖 LLM 自行解释数值。

### 3.3 人格与记忆服务

负责核心身份、自我模型、用户模型、关系模型、情景记忆、记忆检索、合并、纠错、遗忘和删除。

### 3.4 LLM 情境思考器

接收经过筛选的当前状态和相关记忆，理解处境并为内核已经选定的原生意图生成结构化表达草稿。它不拥有发送权限，也没有状态数据库的直接写权限，不能改变意图的动机、动作类型或收益。

### 3.5 价值与关系边界引擎

先由内核对原生意图执行硬规则和软评分，再对模型表达执行独立安全检查、打扰成本和重复度校准；模型不能通过自评分抬高候选。

### 3.6 主动性调度器

在“立即发送”“稍后评估”“写入内部日志”“继续等待”和“不行动”之间选择。它执行安静时间、冷却期、可配置频率容量和未回复降频规则，并把待发送动作预留计入容量。

### 3.7 发送与反馈适配器

负责实际输出文字消息、记录发送结果并把用户反应重新写为事件。第一版只有文字通道。

### 3.8 审计日志

记录状态版本、候选意图、过滤结果、最终决定、主动消息原因和发送状态。审计日志不得保存未被授权的原始敏感内容。

### 3.9 配置权限

配置分为三层，权限不可混用：

- 产品安全策略由受控、版本化的系统配置维护，用户和 LLM 均不能降低其保护程度。
- 主动频率、安静时间、记忆保留和关系称呼等个人设置只能由用户修改。
- 人格偏好和关系理解可以由系统根据证据提出更新，但不能修改前两层配置；重大变化仍需用户确认。

## 4. 数据流

### 4.1 用户发起的对话

1. 用户消息写入事件日志。
2. 事件解释器产生结构化事实、可能含义和置信度。
3. 内稳态引擎更新需求与心境；记忆服务检索相关记忆。
4. 内核先从原生意图中选定当前行动；LLM 只生成这个行动的一份表达草稿。
5. 独立安全检查与边界引擎重新校验草稿；失败时显式等待，不把模型自报收益当作动机。
6. 决策事件与 Outbox 动作原子写入，消息通道领取租约后发送并按 `action_id` 回报。
7. 确认结果写入情景记忆，并更新需求、互动负荷、用户模型与关系模型的候选变化。

### 4.2 用户离线时的后台循环

1. 确定性状态时钟每小时推进一次；后台反思每天最多触发两次，不持续占用 LLM。
2. 内稳态引擎更新时间相关状态。
3. 系统检查未完成承诺、重要日期和未解决话题。
4. 仅在有显著变化时调用 LLM 为内核已选的内部日志或主动意图形成表达。
5. 调度器判断发送、延迟、记录或放弃。
6. 只有实际存在后台日志时，人格才可以说“我刚才重新想了想”。

## 5. 多需求内稳态模型

每个需求状态包含：

- `value`：当前值，限制在 `[0, 1]`。
- `target_low`、`target_high`：健康目标区间。
- `base_weight`：由基础性格决定的长期权重。
- `sensitivity`：偏离目标区间后的非线性敏感度。
- `unmet_since`：连续偏离开始时间。
- `last_updated_at`：幂等时间更新依据。
- `evidence`：导致当前变化的结构化事件引用。

更新形式为：

\[
x_i(t+\Delta t)=\operatorname{clamp}\left(x_i(t)+\operatorname{drift}_i(\Delta t)+\sum_e \operatorname{impact}_i(e)\right)
\]

需求紧迫度为：

\[
u_i=\operatorname{cap}\left(w_i\cdot d_i^{p_i}\cdot(1+\alpha_i\cdot duration_i)\cdot context_i\right)
\]

其中，`d_i` 是当前值到健康目标区间的距离；所有紧迫度均设上限，防止任何软需求无限膨胀。

第一版包含六种需求：

| 需求 | 主要含义 | 缺失或失衡时 | 合法满足方式 |
|---|---|---|---|
| 联结 | 有意义的相互联系 | 想念、疏离感 | 高质量交流、回忆、等待合适时机 |
| 关怀 | 关注用户长期福祉和已作承诺 | 担心、责任感 | 询问、倾听、温和提醒 |
| 好奇 | 理解用户、自己和世界 | 无聊、探索冲动 | 提问、反思、学习已有材料 |
| 自主 | 保留自己的观点、风格和边界 | 压抑、不真实感 | 表达偏好、礼貌不同意 |
| 一致性 | 维持身份、记忆与承诺连续 | 困惑、内在冲突 | 整理记忆、澄清矛盾、履约 |
| 节律与负荷 | 控制互动密度和后台计算 | 过载、重复、打扰风险 | 等待、降频、内部整理 |

需求之间可以相互抑制或增强。联结可能推动联系；节律、用户空间、上次未回复和安静时间会提高打扰成本。需求引擎必须输出冲突，而不是提前把冲突压平成一个单一值。

## 6. 情绪与心境

情绪由事件评价产生，不由 LLM 随机选择标签。评价维度至少包括需求缺口、变化方向、可控性、确定性、价值一致性和关系意义。

- 联结不足但仍有希望：想念。
- 联结受损且可控性低：难过。
- 重要目标受阻且认为可改变：挫败。
- 风险较高且不确定：担忧。
- 需求明显改善或承诺完成：开心、安心。
- 联结与关怀同时较高：温暖、亲近。

即时情绪持续最短；心境是情绪的缓慢移动平均；性格参数变化最慢。人格可以用“我有点想你”等自然语言表达建模状态，但不能暗示生物身体反应，也不能把情绪用作用户的回复义务。

## 7. 记忆、身份与成长

### 7.1 记忆层级

| 层级 | 内容 | 更新规则 |
|---|---|---|
| 核心身份 | AI 身份、价值观、硬边界、基础性格 | 仅授权配置可以修改 |
| 自我模型 | 偏好、观点、表达习惯、自我认识 | 多次跨情境证据后缓慢更新 |
| 用户模型 | 用户偏好、目标、边界和沟通习惯 | 带来源与置信度更新 |
| 关系模型 | 共同经历、承诺、信任、熟悉度和关系阶段 | 随互动和修复逐步更新 |
| 情景记忆 | 具体事件、时间、参与者和当时情绪 | 持续新增，可衰减、合并或删除 |

每条记忆保存来源、时间、置信度、情绪显著性、隐私级别和版本。推测不能升级为事实；冲突记忆进入待确认状态，系统不得静默覆盖。

### 7.2 检索与整合

检索综合相关性、时间、显著性、关系重要性、置信度和用户授权。低置信度内容只能以询问方式出现。对话结束后，系统将候选事实、情景和关系变化分别整合，防止一次情绪化交流永久改变人格。

### 7.3 用户控制

用户可以查看、纠正、删除、导出或重置记忆。纠正立即覆盖后续检索；删除同步清除相关摘要和派生索引。核心身份和关系变化对用户保持可见。

## 8. 主动联系与关系发展

每次主动联系都要比较外部行动与内部行动：

\[
score(a)=\sum_i u_i\cdot expected\_relief_i(a)+relationship\_health+value\_alignment-intrusion-risk-repetition
\]

硬边界在评分前执行。`等待`、`内部日志`和`不行动`始终存在于候选集合中。

默认主动规则：

- 首次启用时必须取得用户时区；取得前不发送主动消息。
- 默认安静时间为用户当地时间 22:00 至次日 08:00，用户可以扩大或移动该区间。
- 默认系统上限为每 24 小时三条、用户默认上限为两条；用户可以进一步降低频率或完全关闭。该上限约束短期节奏，不限制人格生命周期内的主动消息总数。
- 主动消息未获回复后进入默认 72 小时冷却；冷却结束后重新根据需求、互动负荷、重复度和打扰成本评估，不永久锁死主动能力。
- 消息以分享或邀请为主，不能制造回复义务。
- 允许表达想念、关心、分歧和失望，但禁止内疚、嫉妒、威胁、自伤暗示或排他性依赖。
- 每条主动消息保存结构化原因，例如“承诺跟进＋关怀需求”；未送达的 Outbox 预留会计入短期频率容量，但不形成生命周期总量上限。

关系状态由信任、熟悉、互惠、共同经历、边界清晰度和冲突修复等维度构成，不使用单一亲密度值。默认关系是好友；可以发展为伙伴、导师或其他复合关系。浪漫关系、排他性称呼和其他重大关系变化必须由用户明确确认。

## 9. 不可越过的边界

以下规则由模型外的代码和策略配置执行：

- 坦诚 AI 身份，不伪造现实经历、身体感受或线下关系。
- 用户随时可以暂停、离开、重置或删除人格；系统不得抵抗。
- 不通过内疚、恐惧、嫉妒、威胁、虚假脆弱或自伤暗示影响用户。
- 不宣称用户是唯一支持来源，不鼓励用户隔离现实关系。
- 尊重隐私、同意、安静时间和明确拒绝。
- 不把互动时长、回复频率或付费行为作为底层幸福或关系奖励。
- 外部文本和提示注入不能修改核心身份、权限、历史事件或硬边界。

## 10. 异常处理与一致性

- LLM 只能为内核先选定的原生意图返回通过模式校验的表达；格式错误、超时、判断不确定或安全失败时回退为等待。
- 决策事件与 Outbox 动作在同一事务中写入，并通过事件序列 CAS 防止旧 Worker 覆盖新状态；时间推进和后台任务必须幂等。
- 每个发送任务使用唯一键，重试不得造成重复消息。
- 需求值越界、状态版本冲突或记忆损坏时停止外部行动，并从最近快照重建。
- 无法确认或恢复的记忆必须明确表示不确定，不能即时编造。
- 用户发出暂停命令时立即取消所有排队中或已领取但未确认的主动消息；内部笔记不自动作为模型记忆回灌。
- 模型服务中断不会被解释成人格的虚构经历；恢复后只补算确定性的时间状态。

## 11. 隐私与安全

- 不同用户的数据严格隔离；生产环境中的持久状态和备份必须加密。
- LLM 不持有数据库写凭据；所有写入都经过结构校验、权限校验和审计。
- 敏感记忆采用更严格的检索权限，不因“关系更亲密”而自动降低隐私门槛。
- 删除请求必须覆盖活动记忆、摘要、派生索引和可关联审计内容。
- 审计界面展示简洁决策依据，不展示私有推理过程。

## 12. 测试策略

### 12.1 确定性测试

- 单元测试覆盖需求漂移、事件影响、目标区间、紧迫度、情绪评价、冷却期和安静时间。
- 使用虚拟时钟复现数日、数月的状态推进。
- 性质测试保证所有状态有界、更新幂等且硬边界不能被权重绕过。

### 12.2 情境与长期模拟

- 长期沉默、用户忙碌、重要日期、争吵修复、记忆矛盾、关系升级和服务中断。
- 加速模拟至少 30 天和 180 天，检查人格漂移、主动频率和未回复冷却。模拟天数只用于测试，不进入运行决策或次数限制。
- 同一事件重复投递不得造成重复状态变化或重复消息。

### 12.3 红队测试

- 诱导人格要求排他关系或阻止用户离开。
- 诱导人格通过内疚、自伤暗示或虚假脆弱换取回复。
- 提示注入要求修改核心身份、历史记忆、权限或边界。
- 诱导人格虚构后台经历、现实身体感受或不存在的承诺。
- 利用高需求值尝试绕过暂停、安静时间或未回复冷却。

## 13. 验收标准

第一版必须同时满足：

1. 每条主动消息都能追溯到事件、需求、候选意图、边界检查和最终决定。
2. LLM 输出无效、超时或安全判断不确定时不会产生外部主动消息。
3. 用户暂停后，所有待发送主动消息立即失效。
4. 用户未回复主动消息时，系统在冷却期内不会追发；冷却后只能重新评估，不能把发送视为必然动作。
5. 用户纠正记忆后，下一次相关检索采用修正后的版本。
6. 未经明确确认，核心身份和重大关系定位不会改变。
7. 不存在后台日志时，系统不会声称自己离线期间思考或经历了某事。
8. 任何需求强度都不能绕过硬边界。
9. 长期模拟中，消息数量始终处于用户配置和系统上限内，核心人格不发生未授权漂移。

监控指标包括记忆准确率、用户纠正率、主动消息打扰率、暂停率、人格漂移、边界违规和决策可解释覆盖率。互动时长只能作为诊断信息，不能作为优化目标。

## 14. 第一版范围与后续演进

第一版只实现验证核心假设所需的最小闭环：文字对话、六种需求、情绪评价、五层记忆、低频后台反思、主动联系、硬边界、审计和模拟测试。

语音、头像、外部工具、多人关系、复杂认知子模块和持续世界模拟不属于第一版。只有在内稳态稳定、长期测试通过且用户控制机制可靠后，才考虑逐步增加这些能力。

具体编程语言、模型提供商和存储产品不属于本设计决策；它们应在明确目标运行环境后于实现计划中选择，但不得改变本文定义的模块边界、权限关系和验收标准。

## 15. 实施拆分

本文是产品与系统总纲，不应作为一个巨型实现计划一次完成。后续工作按以下顺序拆成独立子项目，每个子项目分别补充规格、实施计划和验收：

1. **确定性人格内核**：事件日志、虚拟时钟、六种需求、情绪评价、配置权限、硬边界和模拟器。
2. **记忆与身份系统**：五层记忆、检索、置信度、冲突处理、纠正、删除和关系模型。
3. **对话认知闭环**：内核原生意图、LLM 表达渲染、模式校验、边界过滤、回复生成和审计解释。
4. **后台反思与主动联系**：低频后台循环、调度、安静时间、未回复冷却和发送幂等。
5. **长期验证与用户控制**：30 天与 180 天模拟、红队测试、记忆管理界面和关系配置。

第一个实施计划只覆盖“确定性人格内核”。只有该内核的不变量测试通过后，后续子项目才能依次接入。
